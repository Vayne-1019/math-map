# 書本編譯規範

給負責編譯《初中數學競賽教程》《高中數學競賽教程》的工作階段。每個工作階段負責一段講次，開始前請完整讀過這份規範，並看過範本：

- 書本版範本：`data/books/cz/L01.txt`（第 1 講開頭到例 2）
- 單元版範本：`data/units/A-1-2/cz-L01.txt`

## 目標：同一份內容，兩個入口

網站上有兩個入口，每一講都要產出這兩層。

1. **入口一「書本順序」**：照原書的講次和段落順序，把書「解壓縮」。原書省略的步驟要補出來，附圖要補齊，數學式全部重新排版。讀者照順序讀下去，不必翻回原書。
2. **入口二「單元地圖」**：把這一講消化後，依網站的單元（例如 A-1-2）整理成精簡的重點圖卡，風格仿「指數律一張圖」：一句話講核心、幾張規則卡、一個「最常錯」、一句結論。要直白到看圖就懂。

**「顯然」的寫法（兩層都要用）**：敘述要簡潔，所以可以寫「顯然」「易知」「同理」。但每一個這類用語都必須附上拆解，讀者覺得不顯然時，點旁邊的 ▼ 就能看到。

## 寫給第一次看到的人（使用者指定）

- **從最小的情形開始，不要去脈絡。** 原書常直接給一般式（例如韋達定理直接寫 $n$ 次），要先補最小的例子：二次 → 三次 → 看出規律 → 一般式。每一步都要讓讀者看得出「這一步在做什麼」，例如先寫 $ax^2+bx+c=a(x-lpha)(x-eta)$，展開後再比較係數。
- **每個例子都要有完整的題目情境。** 不能只寫「$s_1=3,s_2=5$」這種只有懂的人才看得懂的片段；要寫出「已知 $x+y+z=3$……求……」。
- **連續的推導寫成同一個 `aligned`，讓等號對齊**；不要拆成好幾個置中的獨立式子。
- **標題裡的數學符號一樣用 `$…$`**，例如 `title: 看到 $b^2-4ac$ 的樣子`，不要用 b²、e₁ 這類 Unicode 上下標。
- 寫 LaTeX 時注意跳脫：在 Python 字串裡 ``、`` 會變成控制字元（`rac` 變亂碼），要用原始字串或寫入檔案前檢查。

## 著作權（一定要遵守）

網站會公開在 GitHub Pages。

- 講解、證明、詳解一律**用自己的話重寫**，不逐字照抄原書段落。可以沿用原書的數學思路和步驟，數學事實本身不受著作權保護，但文字要是我們的。
- 例題與習題的**題目敘述**可以翻譯或轉寫，要標出處：原書講次與題號；若是競賽題且書中有寫，加上比賽名稱與年份。
- **不要**放原書的掃描圖或截圖。附圖一律自己用 SVG 重畫。
- OCR 全文和掃描檔只在本機參考，不要複製進 repo。

## 參考資料（都在主資料夾，不在 git 裡）

主資料夾：`C:\Users\User\Desktop\教學資源\競賽網頁\`

| 書 | PDF | OCR |
|---|---|---|
| 初中（`cz`） | `data\初中數學競賽教程.pdf`，PDF 頁碼 = 書頁碼 + 6 | `data\ocr\初中數學競賽教程\全文.md`、`raw\p0007.txt`… |
| 高中（`gz`） | `data\高中數學競賽教程（常庚哲、李炯生主編）.pdf`，PDF 頁碼 = 書頁碼 + 3，**簡體字** | `data\ocr\高中數學競賽教程\全文.md`、`raw\` |

講次與起始 PDF 頁碼在 `data/books/<book>/book.txt`。書末附有「習題提示或解答」（初中約 PDF 第 411 頁起，高中約第 388 頁起），習題答案從那裡找。

**OCR 的數學式幾乎都是錯的。** 文字可以參考 OCR，數學式一定要看頁面圖片轉寫。把頁面轉成圖片：

```bash
python -I tools/render_pages.py "<主資料夾>/data/初中數學競賽教程.pdf" "<你的暫存資料夾>/cz" 150 6 12
```

參數依序是：PDF、輸出資料夾、dpi、起始頁索引、結束頁索引。頁索引從 0 起算，所以 PDF 第 7 頁是 6。轉出的圖片用 Read 工具看。

高中那本要轉成**繁體與台灣用語**，例如：函数→函數、递归→遞迴、概率→機率、质数→質數、复数→複數、坐标→坐標、正整数→正整數、抽屉原则→抽屜原理、集合→集合、矢量／向量→向量、二项式→二項式。

## 你可以改的檔案（只有這些）

- `data/books/<book>/L<NN>.txt`：你負責的講次，一講一檔，`NN` 兩位數，例如 `L07.txt`。
- `data/units/<單元代碼>/<book>-L<NN>.txt`：你負責的講次在某個單元的消化版，例如 `data/units/G-4-3/cz-L25.txt`。

**不要改**：`math-map.html`、`tools/`、`data/books/*/book.txt`、`docs/`、其他講次的檔案。有需要改的地方（例如單元大綱缺單元、原書目錄頁碼錯誤），寫在最後的回報裡。

`books/*.js` 是建置產物，**不要 commit**，合併後由主工作階段統一重建。commit 時只加 `data/books` 和 `data/units`：

```bash
git add data/books data/units
```

## 書本版格式 `data/books/<book>/L<NN>.txt`

一個檔案由多個區塊組成，每個區塊以 `=== ` 開頭。**區塊順序就是原書的順序。**

```
=== meta
title: 講名（繁體）
author: 作者
pages: 7-13            ← 這一講在 PDF 的頁碼範圍
units: A-1-2, A-3-1    ← 這一講對應的單元，逗號分隔
status: 完成            ← 完成／草稿

=== text
<p>講解段落，HTML 加 $LaTeX$。小節標題用 <h3>。</p>

=== 定理 1 | 名稱        ← 也可用 定義、引理、性質、公式、推論
zh: 敘述
sol: 證明（可省略）

=== 例 3 | 選填的短標題
src: 1985 年全國初中數學聯賽   ← 原書有寫出處才填
zh: 題目
sol: 解答（網頁上預設收起，讀者自己點開）
ans: 答案（可省略）

=== 習題 5
zh: 題目
hint: 提示
ans: 答案
sol: 解答（有的話）
```

**原書重複收錄的題目不用重錄（使用者指定）。** 同一題在兩本書或兩講都出現時，只在其中一處寫詳解；另一處保留題目（`zh:`），加一行 `same: gz-L13 例 6` 指向寫了詳解的那一處，不寫 `sol:`／`hint:`／`ans:`。網頁會顯示「原書在……也收錄過」並連過去。動手前先用題目文字搜尋其他講次，確認沒有重複。

欄位規則：`zh:`、`sol:`、`hint:`、`ans:`、`src:` 開頭的那一行起算，之後的行都接在同一個欄位，直到下一個欄位或下一個 `===`。`text` 區塊整段都是 HTML。

**每一講的習題都要收**，至少附答案，能附提示更好。

### 數學式

- 行內 `$…$`，獨立一行 `$$…$$`。多行推導用 `\begin{aligned}…\end{aligned}`。
- 數學式裡的中文用 `\text{原式}`。
- 等號串很長時，分成多行寫，不要擠成一行（手機寬度只有約 360px）。

### 「顯然 ▼」標記

```
⟦顯然｜拆解內容⟧
```

- `｜` 前面是顯示的字，例如「顯然」「易知」「同理」「不難驗證」「為什麼這樣拆」，最多 12 字。
- `｜` 後面是點開後顯示的拆解，可以用行內 HTML、`<br>`、`$…$`、`$$…$$`。**不能**用 `<p>`、`<div>`、`<ul>`，因為它會出現在段落中間。
- 用的時機：一個步驟對熟練的人很明顯，但初學者可能卡住。主文保持簡潔，細節收進拆解。
- 不要整段都收進去。主線推理必須留在主文。

### 附圖（SVG）

幾何題、需要圖才看得懂的地方，都要附圖。自己畫 SVG，放在 `text` 區塊或欄位中：

```html
<figure class="bkfig"><svg viewBox="0 0 320 220" width="320" role="img" aria-label="△ABC 與中線 AD">
  <g fill="none" stroke="currentColor" stroke-width="1.5">
    <polygon points="40,190 280,190 120,30"/>
    <line x1="120" y1="30" x2="160" y2="190" stroke-dasharray="5 4"/>
  </g>
  <g fill="currentColor" font-size="15" font-style="italic">
    <text x="112" y="22">A</text><text x="24" y="206">B</text><text x="284" y="206">C</text><text x="156" y="210">D</text>
  </g>
</svg><figcaption>虛線是輔助線</figcaption></figure>
```

- 一律用 `currentColor`，深色、淺色模式才都看得清楚。要強調的線可以用 `stroke="#c2562b"`。
- 寬度不超過 360，`viewBox` 要設。點的位置用心算或寫個小程式算好，圖形要準確，例如等腰就畫成等腰、切線真的相切。
- 輔助線用虛線，並在 figcaption 說明。
- **附圖放在題目（`zh:`）裡**，讀者看詳解時會一直回頭對照圖。原題沒附圖的，最多補一張放在題目上；詳解中途需要的分步圖才放在 `sol:`。（建置時若題目沒有圖，會自動把詳解的第一張圖移到題目。）

## 單元版格式 `data/units/<單元>/<book>-L<NN>.txt`

單元代碼查 `math-map.html` 開頭的 `OUTLINE`（例如 `G-4-3 圓冪與根軸`）。一講可能對應好幾個單元，每個單元一個檔案。

```
=== meta
title: 圖卡標題
from: cz-L01           ← 一定要寫，網站靠它連回書本版
order: 20              ← 同一單元多張圖卡的排序，小的在前；基礎 10–30、進階 40–70

=== body
（HTML）
```

可用的樣式（範本示範過）：

| class | 用途 |
|---|---|
| `hero` | 開頭深藍框：1 到 3 行講核心想法，重點字用 `<b>`（會變黃色） |
| `cards` 包 `card` | 規則卡並排。卡內：`<h4>① 名稱</h4>`、`<div class="rule">公式</div>`、`<div class="eg">小例子</div>` |
| `pill` | 黃色小標籤，一兩個詞點出要訣，例如「指數相加」 |
| `pitfall` | 紅框「⚠ 最常錯」，條列易錯點 |
| `bottomline` | 結尾深色橫條：一句話結論 |

原則：

- **精簡**。一張圖卡大約一個手機螢幕高，詳細推導留在書本版，圖卡只放「看了就會用」的東西。
- 卡片裡的式子要短，長式子拆成兩行或改用小例子。
- 理由用 `⟦為什麼｜…⟧` 收起來。
- 每張圖卡至少有一個具體數字例子。

## 檢查與交付

1. 建置：`python -I tools/build_books.py`，不能有錯誤。
2. 預覽：在你的工作資料夾執行 `python -m http.server <你的埠號>`，或用 preview 工具開，進到 `math-map.html#book-<book>-<講次>` 和 `#u-<單元>` 檢查。確認數學式都排得出來、⟦⟧ 點得開、SVG 在深色模式看得清楚、手機寬度不跑版。
3. 每完成幾講就 commit 一次，訊息例如 `初中第 3–5 講：書本版與單元圖卡`。只加 `data/books` 和 `data/units`，不要 push，也不要合併到 main。
4. 最後回報：完成了哪些講次、寫了哪些單元圖卡、哪些地方原書頁面看不清楚或答案存疑、建議新增或調整的單元。
